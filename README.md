# MRDVS 迈尔微视欧洲市场与渠道研究

这是 MRDVS 视觉传感器欧洲市场研究网站的源文件仓库。网站用于整理重点国家的市场情况、竞品、渠道公司、代理关系和证据来源。

> 本项目是静态网站：浏览器直接读取 HTML 和 JavaScript 文件。它目前没有后台数据库，也不会与 Excel 自动同步。

## 网站结构

| 文件 | 用途 |
|---|---|
| `index.html` | 欧洲市场总览、竞品情况与国家入口 |
| `europe_channel_map.html` | 欧洲渠道地图；读取各国家页的公开渠道数据 |
| `*_channel_detail.html` | 每个国家的详细研究附件 |
| `*_channel_data.js` | 部分国家单独拆出的页面数据 |
| `docs/DATA_MODEL.md` | 国家、竞品、产品、渠道、KP 的关系规则 |
| `docs/PRIVACY.md` | 公开网站与内部客户库的数据边界 |
| `tools/validate-site.ps1` | 发布前检查站内链接、页面标题和潜在联系方式 |

## 数据流

目前的数据更新流程是：

1. 在 Excel 或研究底稿中收集信息；
2. 核验公司官网、伙伴页、社交媒体或其他证据；
3. 按 `docs/DATA_MODEL.md` 建立公司和代理关系；
4. 只把允许公开的数据更新到国家 HTML/JS 文件；
5. 运行网站检查；
6. 在独立分支预览，通过后再合并到 `main`。

Excel 中的修改不会自动出现在网站上。后续可把各国家页面的数据逐步迁移为统一 JSON，让 Excel/脚本和网页共用同一套字段。

## 公开与内部数据

这个仓库会通过 GitHub Pages 公开，因此提交到仓库的内容都应视为可被外部人员下载，包括网页中暂时隐藏的数据。

- 可以公开：公司名称、官方主页、公开办公地址、官方总机、通用销售邮箱、公开伙伴关系和证据链接。
- 仅限内部：个人邮箱、手机号码、LinkedIn 联系人、采购负责人、跟进状态、内部评分和销售备注。
- 内部文件应放入 `private/` 或 `data/private/`；这些目录已被 `.gitignore` 排除，不会被 Git 提交。

详细规则见 `docs/PRIVACY.md`。

## 国家—竞品—渠道—KP 如何对应

代理关系不能直接写成“某经销商属于某竞品”。正确做法是：

- 公司只建立一次；
- 产品只建立一次；
- 每一个“国家 + 竞品 + 产品线 + 渠道公司”组合建立一条代理关系；
- KP 归属于公司或公司网点，通过公司编号与代理关系连接。

这样一个渠道公司可以代理多个竞品，也可以只代理某个竞品的部分产品，不需要重复复制公司和 KP。

## 发布前检查

在 Windows PowerShell 中进入本仓库后运行：

```powershell
pwsh -NoProfile -File tools/validate-site.ps1
```

检查会：

- 阻止不存在的站内链接进入正式网站；
- 确认每个页面都有标题和主标题；
- 列出含潜在邮箱的数据文件，提醒进行公开/内部边界复核。

GitHub 在收到 Pull Request 时也会自动运行同一项检查。

## 初学者 Git 工作流

1. `main` 是当前正式版本，不直接在这里试改；
2. 每个改动建立一个独立分支；
3. Commit 是给本地修改拍一张带说明的版本快照；
4. Push 是把分支上传到 GitHub；
5. Pull Request 是合并前的检查和确认页面；
6. 合并到 `main` 后，GitHub Pages 才会更新正式网站。

如果 GitHub Pages 的发布源不是 `main` 根目录，应以仓库 Settings → Pages 中的设置为准。
