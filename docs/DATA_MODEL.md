# 数据关系模型

## 目的

这套规则用于避免以下混乱：同一个经销商代理多个竞品、同一竞品在不同国家使用不同渠道、同一渠道只代理某个品牌的部分产品，以及同一个 KP 被重复复制到很多记录中。

## 核心实体

| 实体 | 建议编号 | 主要字段 | 说明 |
|---|---|---|---|
| 国家 | `country_id` | 国家名、ISO 代码、GDP、人口、优先级 | 一个国家一条记录 |
| 公司 | `company_id` | 法定名称、常用名称、官网、总部、公司类型 | 竞品、分销商、SI、OEM 都属于公司 |
| 产品线 | `product_id` | 品牌、产品系列、技术类型、应用 | 不把产品名称反复写在关系描述中 |
| 公司网点 | `location_id` | 公司编号、国家、城市、地址、覆盖区域 | 区分总部、分公司和跨境覆盖 |
| 渠道关系 | `relationship_id` | 国家、竞品公司、产品线、渠道公司、状态 | 解决多对多代理关系的核心表 |
| KP | `kp_id` | 公司、网点、姓名、职位、联系方式 | KP 归属于公司，而不是归属于某个竞品 |
| 证据 | `evidence_id` | 来源链接、来源类型、发布日期、核验日期 | 支持每个结论可追溯 |

## 核心关系

```text
国家 ─┬─ 渠道关系 ─ 竞品公司
      │      ├──── 产品线
      │      ├──── 渠道公司
      │      └──── 证据
      └─ 公司网点 ─ 公司 ─ KP
```

## 渠道关系表建议字段

| 字段 | 示例 | 规则 |
|---|---|---|
| `relationship_id` | `REL-DE-SICK-ABC-001` | 永久唯一，不因页面排序改变 |
| `country_id` | `DE` | 关系实际发生或覆盖的国家 |
| `competitor_company_id` | `COMP-SICK` | 品牌方或竞品公司编号 |
| `product_id` | `PROD-SICK-3D` | 精确到被代理的产品线；不确定时标记待核验 |
| `channel_company_id` | `CH-ABC` | 经销商、集成商、区域办公室等 |
| `channel_type` | `VAD` | 使用统一分类，不在每个国家自创名称 |
| `coverage_type` | `local` | `local`、`cross_border`、`online` |
| `status` | `verified_current` | 当前、待核验、历史、无效 |
| `evidence_id` | `EVD-0001` | 至少有一条可追溯证据 |
| `verified_at` | `2026-08-17` | 最后人工核验日期 |

## 多对多关系示例

假设德国经销商 ABC 同时销售 SICK 和 Cognex，但产品不同，应记录为两条关系：

| 国家 | 竞品 | 产品线 | 渠道公司 | 状态 |
|---|---|---|---|---|
| 德国 | SICK | 3D 视觉传感器 | ABC | 当前已核验 |
| 德国 | Cognex | 读码产品 | ABC | 当前已核验 |

KP 只在 KP 表中保存一次：

| KP | 所属公司 | 职位 |
|---|---|---|
| `KP-ABC-01` | ABC | 产品经理 |

查看 SICK 或 Cognex 关系时，通过 ABC 的 `company_id` 找到这个 KP。这样更换职位或电话时只需修改一处。

## 推荐状态枚举

- `verified_current`：品牌方或渠道方当前官方资料可验证；
- `reported_unverified`：有公开线索，但尚未交叉验证；
- `historical`：过去存在，目前不能证明仍有效；
- `invalid`：已经确认不成立；
- `candidate`：适合作为潜在渠道，但尚无代理关系证据。

“候选渠道”与“已代理竞品”必须分开，不能因为一家公司适合合作就写成竞品代理商。

## 数据公开规则

公开网站的数据表不应包含个人联系方式。KP 表属于内部客户库，公开页面只能显示职位类型或使用通用公司联系方式。详细规则见 `PRIVACY.md`。
